# LANCommander 2.2.0 Release Notes

We're back with another milestone release of LANCommander. v2.2.0 improves almost every part of the platform and adds a flexible plugin framework, opening up endless possibilities for customization and extension. The launcher _and_ server have gotten a visual update with a fresh coat of paint that aims to unify the design of both interfaces. Games have been reworked to allow for better versioning, self-updating has been rebuilt from the ground up, and there's so many more changes that we might as well get right into it.

## Breaking Changes

### Steam Integration Moved to a Plugin
Steam support has been removed from the core of the server and launcher. That covers the SteamCMD integration on the server, Steam lobbies in the launcher, and the Steam media grabber. All of it now lives in the official **LANCommander.Plugins.Steam** plugin. If you rely on SteamCMD or Steam lobbies, install the Steam plugin after upgrading. This plugin lives in a separate [GitHub repository](https://github.com/LANCommander/LANCommander.Plugins.Steam), so any issues or bugs should be submitted there.

### Docker Server Engine Moved to a Plugin
The built-in Docker server engine has been removed and is now provided by the official **LANCommander.Plugins.Docker** plugin. Servers that use Docker containers need this plugin installed to keep working. The code for this plugin lives in a separate [GitHub repository](https://github.com/LANCommander/LANCommander.Plugins.Docker), so any issues or bugs should be submitted there.

### Action Types Replace the "Primary" Flag
The **Primary** switch on actions has been replaced by a **Type** field. Existing actions are migrated automatically, and manifests written by earlier versions are still read correctly, so older LCX packages import as before. See [Action Types](#action-types-and-app-links) for what the new types add.

### Game Types
The "Standalone Expansion" and "Standalone Mod" game types have been replaced by two new fields, **Install To** and **Show in Library**. Existing games are converted automatically. See [Games](/Server/Games#upgrading-from-earlier-versions) for the full mapping.

### Server Host and Port Are Overrides
A game server's **Host** and **Port** fields are now overrides. Leave Host blank or Port at 0 and the server uses the address its engine reports. Servers that already have a host and port keep them. See [Server Engine Addresses](#server-engine-addresses).

### Standalone Packager Removed
The standalone LANCommander Packager application introduced in 2.1.0 is gone. Its functionality now lives in the launcher. See [Packaging in the Launcher](#packaging-in-the-launcher).

### AutoUpdater Removed
The separate `LANCommander.AutoUpdater` executable is no longer shipped. The launcher and server now update themselves. See [Self-Updating](#self-updating).

## Plugins
2.2.0 introduces an extensive plugin framework for both the server and the launcher. For the developers out there, a plugin is a .NET class library that is loaded from the `Plugins` directory at startup. Each plugin is loaded into its own isolated load context where services can be registered. They also have the ability to store data in the database via an Entity Framework database context.

Plugins can extend many areas of the platform, including:

- **Server UI**: routable pages, navigation entries placed at specific points in menus, expandable navigation groups, bars docked to the top or bottom of the window, settings pages, and sections in the profile sidebar. Any registered pages can be secured using role-based authorization policies.
- **Pages**: customizable embed codes can be used to render custom components in published pages from LANCommander's micro-CMS.
- **Launcher UI**: views, settings sections, game detail tabs, context menu items, footer widgets, and sections in the new game **Manage** dialog.
- **Metadata**: metadata providers and media grabbers.
- **Game servers**: custom engines, engine settings, consoles, file access, pages and summaries on any server, and sources that list servers LANCommander doesn't store.
- **Data**: plugins can store settings without doing their own file I/O, and can bring their own database context with migrations for SQLite, PostgreSQL, and MySQL. Each plugin is confined to its own tables.
- **Packages**: game export and import, including importing plugin-generated LCX packages through the server's normal import pipeline.
- **Scheduling and events**: recurring jobs and an event bus for reacting to things that happen on the server in real-time.
- **Users**: retrieval of information about users, as well as providing authentication checks on user accounts for exposing LANCommander as a directory service
- **Scripting**: custom PowerShell cmdlets and modules.

### Installing Plugins
Plugins can be installed from a `.nupkg` file or directly from a NuGet feed under **Settings > Plugins**. Installs are staged in `Plugins/.staging` and applied on the next restart, and each plugin keeps its data in `Plugins/{PluginId}/Data`.

Each plugin has a menu on its row that links to the plugin's project website and code repository, opens its settings page if it has one, and shows its release notes. When a plugin is updated, its release notes will be presented to admin users on server restart.

### Launcher Plugins
The server now hosts a small NuGet registry for launcher plugins. Admins can cache launcher plugins on the server, and launchers can then install them from there instead of reaching out to the internet. Plugins marked as required are installed on every connected launcher automatically. The rest are offered to users as optional.

### Documentation
Plugin development is documented in the new [Plugins](/Plugins/Overview) section, which covers [getting started](/Plugins/Getting%20Started), the [extension points](/Plugins/Extension%20Points), and an [API reference](/Plugins/API%20Reference) generated directly from source.

For the developers out there, guidelines on building and distributing plugins are still a work-in-progress. An effort is being made to create a sort of "official unofficial" collection of community plugins that will be listed directly in the server's UI.

### Official Plugins
Alongside the core framework, several official plugins are published under the `LANCommander.Plugins.*` package IDs. These include the Interposer-based Relay, Steam, Docker (both moved out of core, see above) and GOG.

### Community Plugins
Any plugin published to NuGet with the correct tags will automatically show up in the plugin directory. A collection of community-made plugins has been established under the GitHub repository [LANCommander.Community](https://github.com/LANCommander/LANCommander.Community/). This repository belongs to the LANCommander organization, but is lead by community members and provides a way to publish plugins easily using NuGet's trusted publishing without having to manage your own CI/CD workflow. Additionally, plugins published by this repository will receive a NuGet package ID under the reserved `LANCommander.Community.*` prefix.

## Game Versioning
Versioning has been reworked in this version of the platform. Versions were previously only tied to a property on the archive entry, but has now been expanded into a "Version" record. A version groups the archive with its own set of actions, scripts, selected redistributables, redistributable options, and game options. Versions can also exist as drafts, ensuring that the wrong version of the game cannot be installed until it's finalized with a publish.

In the launcher, players can switch between versions from the game's **Manage** dialog. Version switches and updates go through the download queue like any other install. The launcher can also update games automatically when a new version is published.

## Game Options
Games can now define an option schema, similar to the one redistributables gained in 2.1.0. This provides an interface under the game's **Manage** dialog in the launcher where users can change options about the game. The set values can be used with the cmdlet `Get-GameOptions` in a **Before Start** script to modify the game's files or registry entries as needed. Scripts can also be used to write back options using the `Update-GameOptions` cmdlet. This is useful for persisting changes that might have been made in a game using a **After Stop** script.

Game options can be useful for exposing hidden functionality in a game or replacing a game's separate configuration tool. See [Cmdlets](/Scripting/Cmdlets#update-gameoptions) for syntax and examples.

## Self-Updating
The launcher and the server now update themselves, without a separate updater application.

### Launcher
The launcher checks your LANCommander server for a newer launcher. When one is available, a badge appears beside the profile dropdown, and updates can also be checked for and started from **Settings > Updates**. The launcher warns you before updating if the download queue still has unfinished items.

After the update, a **What's New** dialog shows the release notes for every version newer than the one you updated from. If the new version fails to start, the launcher rolls back to the previous version and tells you why the update failed.

### Server
The server can download and apply its own updates from **Settings > Updates**. It stages the new release, stops, swaps in the new files, and starts the updated server. When it runs as a Windows service or under systemd, it exits so the service manager starts the updated files. If the updated server doesn't start, the previous version is restored. If an update is interrupted while files are being swapped, it's rolled back the next time the server starts.

The first administrator to sign in after an update sees its release notes, or the reason it was rolled back. The notes can be opened again with the **Release Notes** button under **Settings > Updates**.

### Unified Design
The launcher has been fully redesigned to mature previous design and establish a uniform style. As always, quick access to your games and putting art front and center were the top priorities. The left rail is now always shown and contains navigation to the library and depot. The library shows carousels of recently played games and your collections, and the game details view has been reworked to give the best look at your game's rich metadata. Big picture mode has also gained status bar items for battery, volume, and time.

### Manage Dialog
Game options, versions, install options, and save management have moved into a new **Manage** dialog on each game. Plugins can add their own sections to it, and per-game [Interposer](/Interposer) settings live here as well.

### Network Relay
With the `LANCommander.Plugins.Relay` official plugin installed, games can now have their network traffic routed through your LANCommander server. By exposing a port (default of 41300) to your LANCommander server, users outside of your network can now play games as if they were sitting right next to each other. This requires no VPN, virtual network adapter, or any drivers and works over standard UDP/TCP sockets.

Of course there are some limitations and compatibility may vary from game to game:
1. Latency will be higher depending on distance from player to server to player
2. Direct peering connections are implemented, but may be limited for users behind a CGNAT
3. **Traffic is unencrypted**

Since this happens on an API level with function hooking, _only traffic coming to/from the game_ is routed through the relay. Launcher authentication, downloads, chatting, etc. via LANCommander are still sent over HTTP(S).

This functionality is part of [Interposer](/Interposer). Any bugs or issues should be reported to that project's [GitHub repository](https://github.com/LANCommander/LANCommander.Interposer).

### Packaging in the Launcher
The separate packaging application is _gone_ and has been integrated directly into the launcher. Authenticated admins can now package games from the launcher with some improvements:
- Monitoring runs in separate 32-bit and 64-bit worker processes, so installers that spawn children of either bitness are captured into one change set.
- Elevated installers are tracked properly. When an installer needs administrator rights, the launcher offers to restart the capture elevated and raises a desktop notification, since the installer's own consent dialog is usually covering the launcher.
- Install directory detection has been improved and uses the common ancestor of every file written.
- A new **Additional Changes** step baselines the install folder after the installer finishes, so no-CD patches, widescreen fixes, config edits, and mods can be captured too.

See the [Packaging](/Packaging/Overview) documentation and the [Wizard Walkthrough](/Packaging/Wizard) for details.

### Script Debugger
The launcher now includes a full script debugger. Scripts can be stepped through with breakpoints, and their variables can be inspected, including in scripts that run elevated. LANCommander's scripting engine is PowerShell, and debugging it now works much like it does in a full IDE.

### Profile
Players can change their alias and avatar from the launcher, as far as the server's authentication settings allow.

### Chat
Chat in the launcher has had a round of improvements:
- Messages show avatars, and a typing indicator shows when someone is writing a reply.
- New messages play their own sound, and on Windows the taskbar button shows the unread count and flashes when a message arrives while the launcher isn't in front.
- Threads can be deleted. Deleting a thread only takes it off your list, and everyone else in it keeps it.

### Presence
The launcher now shows who is playing what. While someone is in a game, their name is highlighted in chat and they appear under **Playing Now** on the game's page. Hovering over their name shows the game, its icon, and how long they've been playing. The game's action bar shows how many people are playing, with their names in a tooltip. Games run through the LANCommander Interposer can report more detail, such as the map, score, or party size, with the appropriate game patch. Players control what they share from **Activity Status** in the menu under their name. This rich presence is also reported to Discord, if you're into that sort of thing.

### Interposer
LANCommander Interposer injection and its options can now be configured from within the launcher, per game, from the Manage dialog. The launcher also supports the Interposer network relay, which can be switched on Windows from **Network Relay** in the profile menu. Switching it saves the setting and takes running games off the relay, or puts back the ones that were started on it. Launcher plugins can register their own relay endpoints.

### Action Types and App Links
Actions now have a **Type** rather than a Primary flag. Alongside **Primary** and **Secondary**, two new types are available:

- **Config** actions are for things like a game's configuration executable.
- **Join** actions define the arguments a game needs to join a specific server, lobby, or host directly.

A new **Servers** tab on a game's details lists its servers. The `lancommander://` app scheme has been expanded so links can start a game or join a server directly, e.g. `lancommander://game/{GameId}/play` or `lancommander://game/{GameId}/join?ServerHost=...`. Link parameters are filled into the `{Name}` placeholders of the action's arguments.

### Process Tracking
The launcher now follows every process a game spawns. Games that use a separate loader stay marked as running until the last of their processes exits, and stopping the game stops all of them. On Windows this uses a job object. On Linux the process tree is followed by parent process ID.

### Offline Fallback
If the last server you used can't be reached, the launcher now gives it five seconds to respond and then goes into offline mode. If you have stored sign-in credentials, your cached library opens so you can play installed games without the server. Without them, the login screen opens with the server marked offline, and you can pick a different server. Thanks to [@aaronpowell](https://github.com/aaronpowell) for this one ([#490](https://github.com/LANCommander/LANCommander/pull/490)).

### Download Queue
- A game waiting in the queue shows **Queued** on its install button, and the play button shows **Uninstalling** while a game is being uninstalled.
- Progress in the queue and on the taskbar no longer jumps around or shows values from earlier in the install, and a finished or failed install no longer has its taskbar progress put back by a late update.
- Download progress is shown when installing tools and redistributables ([#463](https://github.com/LANCommander/LANCommander/issues/463)).
- Items with no icon or cover show an icon based on what's being installed (game, expansion, mod, tool, or redistributable).
- A game is no longer announced as installed until the redistributables queued for it have finished. Plugins listening for the installed event and the server's install report now see the install once it's actually ready to play.
- Installs run in their own short-lived scope, which fixes problems with installing and uninstalling the same game more than once in a session.

### Archives with Japanese File Names
Zip archives whose file names aren't marked as UTF-8 are now decoded correctly. Many tools, including Windows Explorer on a Japanese system, write file names in Shift-JIS without saying so, and those names used to come out garbled. The server's archive browser and the launcher decode names the same way, so action paths picked on the server match the files on disk.

### Saves and Uninstalling
- Uploading a save no longer keeps the save files locked, which could stop the game from being uninstalled afterward.
- A warning is logged when a save path matches the game's entire install directory, which would pack the whole game as its save. LANCommander's own metadata is never included in a save.
- If a game's files can't be deleted during uninstall, for example because they're in use, the uninstall now fails with an error and the game stays installed so you can try again. Previously it was marked as uninstalled.
- Uninstalling runs on a separate thread, so the UI no longer hangs while files are being deleted.

### Linux
- Actions built for Linux now launch natively on Linux instead of always being wrapped by a compatibility runtime.
- The discovery beacon now broadcasts correctly on Linux hosts ([#464](https://github.com/LANCommander/LANCommander/issues/464)).

### Performance
Progress bars and spinners no longer animate when they aren't visible, which cuts CPU and GPU usage while idle. Animated covers pause when not focused or hovered, bitmaps are disposed on navigation, and launcher builds ship a trimmed-down copy of VLC.

### Radzen UI
The server UI has been moved from AntDesign to Radzen, along with a design refresh across the application to match the launcher's design language. The dashboard now shows more information about your server, games have gained more complex filtering, the script editor has been refined and adds a few extra features, and pages have leveled up with better CMS-like functionality.

### Chat
Chat is now available in the server UI under **Chat** in the main menu, for administrators and signed-in users alike. Conversations are shared with the launcher, so messages sent from either one show up in the other as they arrive. It matches the launcher's look, shows when someone is typing, notifies you of new messages, and lets you delete threads from your own list.

### Global Variables
Scripts can now use global variables defined on the server under **Scripting > Variables** ([#301](https://github.com/LANCommander/LANCommander/issues/301)). They are available in the PowerShell runspace and are offered as completions in the script editor.

### Match Statistics
The server can now record what happens in multiplayer matches, including events, results, per-player statistics, and attachments such as demos or logs. Players are linked to LANCommander users wherever the server can identify them. How far reported data is trusted depends on the account that reports it. Administrators and plugins are authoritative, and player clients are limited. The data is exposed through a JSON API, which tools such as Grafana can query, and through plugin interfaces. Match statistics can be configured in settings and viewed in a panel on each server. See [Match Statistics](/Server/Match%20Statistics) for details. Game server Docker images under the LANCommander organization are slowly gaining support for capturing and submitting these statistics.

### Webhooks
Server events can now be delivered to outbound webhooks under **Settings > Integrations > Webhooks**. Each webhook can subscribe to specific events and have its own timeout and retry limits. Signing with a shared secret is optional. Webhook editors show a preview of each event's payload, can send a test delivery, and keep a delivery history with the exact JSON that was sent. Events cover games, versions, redistributables, tools, servers, media, libraries, saves, keys, authentication, and presence. See [Webhooks](/Server/Webhooks) for details.

### Personal Access Tokens
Users can now create personal access tokens from their profile, limited to specific scopes such as reading or reporting matches. A dedicated game server reporting match statistics, for example, should use a token owned by an administrator and limited to **Report matches**.

### Game Servers
- **File manager**: game servers now have a file manager and editor. The underlying contract is also exposed to plugins, so plugin-provided engines such as Docker can supply their own file access.
- **Filters**: the **Servers** page has a filter rail like the one on the **Games** page. Views cover all servers, running, stopped, errored, autostart, servers with no game, and servers added this week. The list can also be narrowed by status, game, engine (Local, Remote, or a plugin's engine), and autostart method. Servers listed by plugin sources have their own view.
- **Autostart**: servers set to start on player activity are now started again after an error, as long as they're stopped or errored. A server set to autostart that no engine manages is logged as a warning instead of being skipped silently.

### Server Engine Addresses
Plugin-provided server engines can now report where players can reach their servers, such as the address and published port a Docker container was given. A server's **Host** and **Port** fields are now overrides: leave Host blank or Port at 0 and the server uses what the engine reports. The server editor shows the reported values next to these fields. Plugin authors can find details under [Extension Points](/Plugins/Extension%20Points).

### Remote Servers
Remote hosts under **Settings > Servers** have a new **Add Servers** option, on by default. The host's servers are added as Remote servers as they appear, named and linked to their game the way the host has them, so they can be started with player activity, given actions, and monitored without setting each one up by hand. A server you delete isn't added again. If a host can't be reached or no longer has a server, the server's General page says so.

### LANCommander HQ
- Redistributables can now be imported from LANCommander HQ through its authenticated package registry ([#466](https://github.com/LANCommander/LANCommander/issues/466)).
- The duplicate HQ provider dropdown in the media picker has been removed, and the provider dropdown now supports selecting multiple providers.
- A new button downloads art automatically.
- When HQ media can't be downloaded through HQ, the server falls back to downloading it from the original source.

### Issues
Reporting issues via the launcher has been restored, and issues now support titles, pinning, and attachments. Issues are also visible in the associate game's details in the launcher.

### Pages
Pages have had a round of fixes and new features. They can now embed content, have a preview toggle, search, and some appearance customization. Parent pages can have their own content, and pages can link to games, redistributables, and servers. Plugins can add their own embed codes, which are listed in the page editor's **Insert** menu. Deleting a parent page now warns how many child pages it will remove.

### Importing and Exporting
Importing has been reworked to handle versions, and various issues with importing certain records have been fixed. Importing a game that already existed with external IDs (such as an IGDB ID) no longer fails on SQLite, and a migration on both the server and the launcher repairs any IDs that were affected.

### Audit Fields
The created on/by and updated on/by audit fields have been... audited... and the backing code has been fixed as some records didn't get these filled out properly on save.

### Security
- An issue where downloading logs and the live log stream could have been visible to non-admins has been fixed.
- An issue where API and RPC control of game servers could have been accessed by non-admins has been fixed.
- A server's HTTP paths can no longer serve files outside their configured folder.
- Password checks made by plugins follow the server's sign-in rules. Locked-out and unapproved accounts are refused, nothing succeeds while password sign-in is turned off, the result doesn't reveal whether a user exists, and failed attempts are rate limited to five per user name in five minutes.

## Scripting
- `Get-GameOptions` reads a game's options, and `Update-GameOptions` writes them back. See [Game Options](#game-options).
- Global variables are available in every script. See [Global Variables](#global-variables).
- Scripts for addons get `$BaseInstallDirectory` and `$BaseGameManifest`, which point to the base game's install directory and manifest. For a main game they're the same as `$InstallDirectory` and `$GameManifest`.
- A new cmdlet gets local game details from the launcher.

**@aaronpowell | PRs [#469](https://github.com/LANCommander/LANCommander/pull/469), [#475](https://github.com/LANCommander/LANCommander/pull/475), [#480](https://github.com/LANCommander/LANCommander/pull/480): Plugin Integration**
Aaron filled out much of the server side of the plugin framework. #469 added route and navigation extensions, direct LCX package imports through the server's existing import pipeline, and a streaming LCX builder. It also closed a gap where plugin pages without an `[Authorize]` attribute could be reached anonymously. Plugin routes are now authorized by the server and default to administrators only. #475 added metadata lookup and version redistributable contracts so plugins no longer need to reference server internals. #480 gave plugins cancellable, host-routed access to game server files.

**@aaronpowell | PR [#483](https://github.com/LANCommander/LANCommander/pull/483): Server Events and Webhooks**
Added the pluggable server event system and outbound webhooks, followed by management pages, payload previews, test deliveries, optional signing, and formatted delivery history.

**@aaronpowell | PR [#490](https://github.com/LANCommander/LANCommander/pull/490): Launcher Offline Fallback**
Made the launcher fall back to offline mode when the saved server can't be reached, opening the cached library for players with stored credentials.

**@aaronpowell | PR [#476](https://github.com/LANCommander/LANCommander/pull/476): Release Version Synchronization**
Centralized the .NET version properties and added release automation that keeps checked-in versions aligned with release tags. It validates SemVer and assembly versions, protects against downgrades, and is safe to re-run.

**@aaronpowell | PR [#451](https://github.com/LANCommander/LANCommander/pull/451): Incremental Frontend Builds**
Proposed skipping the frontend build steps when their inputs haven't changed. It was adapted into the codebase in [#482](https://github.com/LANCommander/LANCommander/pull/482), which cut a no-op server UI build from about 15.5 seconds to about 3.5.

**@celinhodaltro | PR [#477](https://github.com/LANCommander/LANCommander/pull/477): PCGamingWiki UTC Release Dates**
Fixed release dates from PCGamingWiki being parsed in local time rather than UTC.
